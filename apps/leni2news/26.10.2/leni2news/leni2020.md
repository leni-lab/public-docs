# LENI2020 interface

This contract describes the file handoff from LENI2020 to leni2news.

Regular distribution exports have no future send time: LENI2020 holds
scheduled messages until `transmit_at` is due before exporting them.
leni2news does not schedule delivery. See
[LENI time semantics](https://github.com/leni-lab/leniextract/blob/main/docs/time-semantics.md)
for the publication lifecycle and the preview exception.

## Producer responsibilities

- write each export in one open-write-close operation
- keep the file open throughout writing so the Windows exclusive-access check
  cannot succeed before completion
- do not modify, replace, or reopen completed files for writing
- generate names independently of files remaining in the export directory
- run one name-generating producer process per export directory
- prevent collisions between pending exports and leave processing directories
  to the importer

Export names follow the canonical
[News Store grammar](https://github.com/leni-lab/store-contracts/blob/main/docs/news-store.md),
with source `leni`, for example `1789203039_001.leni.json`. The importer
validates this grammar. Store allocation is defined by the linked contract.

LENI2020 `export_published` assigns `data.released_at` and `data.published_at`
from the processing-time value `$^T` before calling `export_dist`. That path
uses the same value for the export filename. `export_dist` itself does not
validate those fields, so other callers need not have this equality.

Within one producer run, a new highest timestamp resets the suffix to `001`.
Equal or backward values increment the suffix, but the filename timestamp still
uses the current processing-time value. The in-memory counter is not persistent
across restarts. The exporter therefore does not guarantee ordered or
permanently unique store names. It must still avoid overwriting pending input:
the importer cannot recover bytes already lost in the export directory.

## Importer handoff

Run one importer per input directory. Multiple importer inboxes may share a
store. leni2news applies the
[regular input rules](https://github.com/leni-lab/store-contracts/blob/main/docs/news-store.md#regular-input-ordering) to completed exports.
Name preservation is best effort under that contract.

The importer uses Filefeed with the stability windows in
[input settings](settings.md#input). These are observations of size and mtime,
independent of LENI's clock. They improve handling of bursts but do not prove
that every export of a source second has arrived. Clock skew, delayed exports,
and delayed filesystem visibility can therefore require name corrections.

After successful publication, the source moves to `done`. The
[command line](cli.md) defines batch, watch, retry, and shutdown behavior.
[Troubleshooting](troubleshooting.md) covers blocked inputs and recovery.
